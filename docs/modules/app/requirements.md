# app 模块｜需求

## 目标
- 提供本地脚本入口：按 `watchlist` 批量刷新分钟数据到本地缓存，并输出可读日志（不做推送）。

## 范围（已确认）
- 以 `docs/PRD.md` 为准，仅实现已文档化功能。
- 支持“盘中刷新”最小闭环：watchlist → data.ensure_1m → 输出统计。

## 输入
- 自选股文件：`config/watchlist.csv`（由 watchlist 模块定义）
- 数据目录：`data/`（SQLite 缓存路径由 data 模块定义）

## 输出
- 控制台日志：
  - 每次刷新：处理的标的数、每只标的的 `upserted_changes`、失败列表
  - 可选：信号候选输出（后续 signals 打通后启用）
  - 可选：缺口统计（后置增强）

## 运行模式（初版）
- 单次刷新（run once）：用于手动补数据
- 循环刷新（loop）：按固定间隔（默认 60s）重复执行单次刷新

## 刷新窗口策略（初版）
- 每次刷新只覆盖最近 `window_minutes`（默认 60 分钟）以控制请求量
- 调用 `data.ensure_1m`：发现缺口才拉取在线源并回填缓存

## 不做（后置）
- 图形界面（UI）
- 通知推送（短信/微信/邮件/桌面弹窗/Webhook 等）
- 自动下单/券商交易接口
- 全市场扫描（仅 watchlist）

## 验收点（MVP）
- 能加载 `config/watchlist.csv` 并校验
- 能对 watchlist（可过滤 group）批量执行刷新并写入 `data/bars.sqlite`
- 在同一时间窗内重复运行，绝大多数情况下 `upserted_changes=0`（缓存优先生效）

## 信号联动（增强）
- 在完成刷新后，可选择对每个标的运行 signals 模块策略（初版：短线突破 5m），并在控制台输出候选信号。
- 信号计算需要更长窗口（例如 5m lookback=20 需要至少 ~105 分钟数据）；因此信号窗口与刷新窗口可分离配置。
- 支持扫描模式：对窗口内每根 5m bar 扫描触发点（用于盘中/盘后复盘与“今天出现过哪些信号”）。
