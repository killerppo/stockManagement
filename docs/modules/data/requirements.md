# data 模块｜需求

## 目标
- 获取与管理 A股分钟级数据（免费优先），并向下游提供稳定的数据接口。

## 范围（已确认）
- 自选规模约 50 只
- 分钟级（1m）为基准；更高周期可聚合（聚合规则后续在此文档补充）
- 数据源可替换：数据获取层与指标/信号层解耦

## 模块边界
- 本模块负责：获取/缓存/校验/聚合 K线数据，并提供统一的读取接口。
- 本模块不负责：指标计算、买卖信号、推送通知、下单交易。

## 数据契约（Bar Schema）
以 1 分钟 Bar 为最小单位（`freq="1m"`），字段如下：
- `ts`：分钟结束时间或开始时间（二选一，必须全项目一致；初版以“分钟开始时间”定义），时区 `Asia/Shanghai`
- `open`/`high`/`low`/`close`：价格（float）
- `volume`：成交量（int，单位由数据源决定，必须通过 provider 元信息暴露；下游若仅做“量比/相对变化”可不依赖绝对单位）
- `amount`：成交额（float，CNY；可选，缺失时为 `None`）
- `source`：数据源标识（string）

## 交易时段对齐（A股）
- 连续竞价：09:30–11:30，13:00–15:00（北京时间）
- 午间休市分钟不应出现在 Bar 序列中；如出现必须标记为数据异常。
- 集合竞价/盘前盘后：初版不强制接入；若数据源提供，必须单独模式处理，不得静默混入常规 1m Bar。

## 数据质量校验（必须）
- 时间序列：按 `ts` 严格递增；不允许重复分钟（同一 `symbol + ts` 只能有一条）
- 字段合法性：OHLC 必须为正数；`high >= max(open, close)` 且 `low <= min(open, close)`
- 缺口检测：同一交易日内，若连续竞价时段缺少分钟，需输出缺口信息（用于上层显示/日志）
- 异常可见：校验结果需以结构化方式返回（问题列表），并可被记录到日志模块（后续对接）

## 聚合（从 1m 到 5m/15m/60m）
- 聚合输入：同一交易日同一标的的 1m Bars
- 聚合输出：
  - `open`：该桶第一根 bar 的 open
  - `high`：桶内 max(high)
  - `low`：桶内 min(low)
  - `close`：该桶最后一根 bar 的 close
  - `volume/amount`：桶内 sum
- 桶边界：以交易时段起点为锚点（09:30、13:00），按 N 分钟整除划分；跨午间休市不合并。

## 数据源适配（免费优先、可替换）
- 适配层接口必须抽象为 `DataProvider`（命名可调整，但语义一致）：
  - `fetch_1m_bars(symbol, start, end) -> list[Bar]`
- 初版必须提供一个“离线可用”的 provider（例如 CSV/本地文件导入），用来支撑无数据源情况下的开发与复盘。
- 任何第三方/网络 provider 都必须可插拔，并支持限流与重试（策略后续补充）。

### 在线 Provider（初版落地）
在线数据源主用（免费优先，可在 app/脚本中切换）：
- Eastmoney（东方财富）K 线接口：无需 Token，拉取 1m K 线并映射到本模块 Bar Schema
  - 风险：公开接口可能变更/限流/封禁
  - 要求：必须做限流/重试/退避，并将异常显式暴露给上层（不可“静默不更新”）
  - 约束：单次请求返回最多约 2000 根 1m bars，provider 需做分页/按日回补以覆盖长区间（必要时使用按日时间段参数）
  - 时间戳口径：若源数据给的是“分钟结束时间”（常见表现为开盘第一根为 `09:31`），provider 必须归一化为“分钟开始时间”（减去 1 分钟）

在线数据源（免费优先，可选/补充）：
- AkShare：
  - 通过 AkShare 的分钟 K 线接口拉取数据（内部可能仍依赖公开数据源）
  - 特点：部分周期（如 5m/15m/30m/60m）历史更长，适合用于信号扫描/回测
  - 限制：1m 历史可能只有最近若干交易日；当用户请求超出可用范围时，上层需通过日志/提示告知“数据覆盖不足”

在线数据源可选备选（需要权限/Token）：
- Tushare Pro：可用时作为备选（需要 `TUSHARE_TOKEN`，且分钟接口可能受权限限制）

统一约束（对所有在线源生效）：
- **缓存优先**：读数据优先走本地 SQLite；仅在缺口明显或用户显式刷新时才访问在线源
- **可替换**：任何在线源都必须通过 provider 插拔实现；不得在业务逻辑中写死某个 URL 或字段
- **异常可见**：超时/限流/字段异常必须返回结构化错误，供上层展示/记录

### CSV 离线 Provider（初版约定）
每个标的一个文件：`<csv_dir>/<symbol>.csv`，要求：
- 必须包含列：`ts,open,high,low,close,volume`
- 可选列：`amount`
- `ts` 使用 ISO 格式（建议包含时区，如 `2026-02-06T09:30:00+08:00`；若无时区则按 `Asia/Shanghai` 处理）

## 本地缓存与存储
- 初版使用本地持久化（SQLite 优先）以支持：
  - `upsert`（按 `symbol + ts` 去重写入）
  - 按时间范围读取 1m Bars
- 缓存目录为仓库根目录下的 `data/`（已在 `.gitignore` 中忽略，不入库）

## Provider 回退（建议）
当主在线源不可用时，允许配置“回退 provider”：
- 调用顺序：主 provider → 次 provider → ……
- 行为：某一 provider 请求失败或返回空数据时，尝试下一个 provider；若全部失败，返回最后一次错误（并记录所有尝试信息用于排障）

## 对外接口（供上层模块使用）
必须提供最小读取能力：
- `get_bars(symbol, freq, start, end)`：
  - `freq` 支持 `"1m" | "5m" | "15m" | "60m"`
  - 若请求非 1m：
    - 优先从缓存读取 1m 后在本地聚合
    - 若缓存对目标区间覆盖不足，且 provider 支持直接拉取该频率（例如 AkShare 的 5m/15m/30m/60m），允许直接拉取并返回（并在日志中提示实际覆盖范围）

并提供“缓存优先”的刷新能力（初版可简化实现，但语义必须存在）：
- `ensure_1m(symbol, start, end)`：优先读取缓存；发现明显缺口时才向 provider 拉取并回填缓存

## 配置（初版）
- 数据目录（SQLite 路径、CSV 路径等）可配置，默认不需要复杂配置文件。

## 验收点（MVP）
- 能导入本地 CSV 的 1m Bars 并写入缓存（去重）
- 能从缓存读取指定区间 1m Bars 并通过校验（输出校验结果）
- 能将 1m 聚合为 5m/15m/60m 且结果可复现
- 在没有网络数据源的情况下，依然可用（离线 provider 可跑通）
